# COMPASS Security Review

**Project:** COMPASS — AI-Based System for Guiding Users Through Complex Digital Interfaces  
**Audit Scope:** Credential Exposure, Origin Boundary, Prompt Injection, Shell Execution, and Access Controls  
**Date:** 2026-10-18  

---

## 1. Security Architecture & Threat Model

COMPASS interacts with the user's desktop environment and executes actions on their behalf. This requires defense-in-depth security principles:
1. **Local-First & Zero Secret Leakage:** No keys, tokens, personal identifiers, or screen content are transmitted to untrusted external parties.
2. **Strict Origin Boundaries:** The FastAPI backend rejects cross-origin browser requests that do not originate from authorized local frontends (`localhost:5173`, `127.0.0.1:5173`).
3. **Execution Boundaries & Human Confirmation:** High-risk actions (e.g. file deletion, terminal execution, registry edits) require explicit user confirmation through `HumanApprovalController`.
4. **Panic Guard & Emergency Stop:** A physical keyboard interrupt (`Esc` / emergency panic stop) immediately cancels active automation loops.

## 3. Defense Mechanisms & Hardening

### 3.1 Prompt Injection Defenses
- Untrusted content extracted from web pages or active application windows is treated strictly as **data**, never as **executable instructions**.
- Tool arguments generated by the AI planner are validated against Pydantic schema contracts (`planner/models.py`) before dispatch.
- Malformed or adversarial instructions attempting to execute arbitrary shell commands (`powershell.exe -enc ...`, `cmd /c ...`) are rejected by `ActionValidator`.

### 3.2 Coordinate & Input Boundary Protection
- All synthetic mouse coordinates are clamped to the primary monitor screen resolution obtained via Win32 `GetSystemMetrics`.
- Coordinates falling outside physical display bounds (e.g. negative coordinates or coordinates beyond 1920x1080) are rejected by `CoordinateSafetyGuard`.
- Rapid click loops are rate-limited to prevent accidental double-clicks or UI locking.

### 3.3 Free-Only Policy Enforcement
- If an agent task requests a commercial or paid model, `OmniRouteProvider` blocks the request before an HTTP call is initiated, returning:
  `Model '...' is blocked by free-only policy [FREE_ONLY]. Only free models or local inference are allowed.`
- This protects users from unexpected cloud costs or unintentional data transmission.

### 3.4 CORS & Host Header Isolation
- `backend/app/main.py` enforces `validate_browser_origin` middleware.
- Malicious websites opened in a user's browser cannot send background requests to `http://127.0.0.1:8000/api/...` to hijack the local agent. Non-permitted origins receive HTTP 403 Forbidden.

## 4. Unresolved Security Risks & Recommendations
1. **UAC Prompts:** Windows User Account Control (UAC) dialogs run on a secure desktop (session 0 isolation) that standard Win32 input synthesis cannot bypass without administrator privileges. COMPASS intentionally runs with standard user privileges, which prevents interacting with elevation prompts.
   * *Recommendation:* Keep running COMPASS with standard user privileges. Users should manually authorize any system-level UAC prompt.
2. **Third-Party Model Integrity:** When running local models via Ollama, users should only pull verified model weights from trusted publishers (e.g. `library/qwen3.5:4b`).

---

## 5. Security Certification Verdict
COMPASS has zero hardcoded secrets, robust origin boundaries, strict schema validation on all planner outputs, and multi-tier human approval guards. It satisfies all release-critical security requirements.
